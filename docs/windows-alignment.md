# Windows / macOS 功能对齐

## 已对齐能力（2026-07-11）

### 采集与差异模式

每个环境独立保存两个开关：

- `collectorDebugEnabled`：只开放本机 CDP 通道，不注入页面脚本。
- `fingerprintEnabled`：开放本机 CDP，并注入 `navigator.hardwareConcurrency` 与 `navigator.deviceMemory`。

两个开关可以组合。默认均关闭，保持基础模式。旧版配置缺少采集字段时按关闭处理，原有 `fingerprintEnabled` 语义不变。

调试端口优先使用 `41000 + 环境编号`，只绑定 `127.0.0.1`；端口冲突时最多向后尝试 10 个端口，界面展示实际分配结果。运行中、启动中或关闭中的环境不能修改模式。

模式管理窗口提供搜索、仅显示可编辑环境，以及为当前可编辑结果批量启用或关闭采集模式。

### 配置恢复和最近使用时间

配置保存流程：

1. 编码到临时文件；
2. 将现有 `config.json` 复制为 `config.json.bak`；
3. 原子替换主配置。

配置读取失败时依次：

1. 将损坏主配置保留为 `config.corrupt-<时间戳>.json`；
2. 尝试恢复 `config.json.bak`；
3. 扫描 `Profiles/pN` 重建最小环境列表；
4. 没有任何可恢复数据时才使用默认配置。

`lastUsed` 由环境启动/停止流程写入 Profile 配置。旧配置或磁盘重建时，环境目录修改时间只作为兜底值。

读取配置时还会过滤非法编号和重复 folder，避免异常但仍可解码的 JSON 导致运行时状态字典冲突。磁盘重建只接受实际目录，不把同名普通文件识别为环境。

## 平台差异边界

以下 Windows 能力不迁移实现，只保持用户操作语义一致：Edge 备用引擎、注册表默认浏览器注册、MSI 安装器、命名管道单实例通信和 Windows 托盘鼠标行为。macOS 继续使用独立 Chrome 副本、系统 URL 事件、菜单栏与 Sparkle 更新机制。
