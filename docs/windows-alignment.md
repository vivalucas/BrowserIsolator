# Windows / macOS 功能对齐

## 核心行为契约

### 采集与差异模式

每个环境独立保存两个开关：

- `collectorDebugEnabled`：只开放本机 CDP 通道，不注入页面脚本。
- `fingerprintEnabled`：开放本机 CDP，并注入 `navigator.hardwareConcurrency` 与 `navigator.deviceMemory`。

两个开关可以组合。两端新建环境（含首次生成）默认开启采集、关闭差异。已有环境保留原设置，旧版配置缺少采集字段及磁盘重建时仍按关闭处理，原有 `fingerprintEnabled` 语义不变。

采集模式优先使用 `41000 + 环境编号`；仅开启差异模式时优先使用 `40000 + 环境编号`。两种模式同时开启时以采集端口为准。端口只绑定 `127.0.0.1`，冲突时最多向后尝试 10 个端口，界面展示实际分配结果。运行中、启动中或关闭中的环境不能修改模式。

Chrome 启动参数与 Windows 保持一致：使用独立 `--user-data-dir` 和 `--no-first-run`，仅在采集或差异模式需要时添加本机 CDP 参数，不传入会暴露测试运行特征的 `--test-type`。

模式管理窗口提供搜索、仅显示可编辑环境，以及为当前可编辑结果批量启用或关闭采集模式。无匹配结果显示空状态，没有可改变的结果时禁用相应批量按钮。

### 配置恢复和最近使用时间

配置保存流程：

1. 编码到临时文件；
2. 将现有 `config.json` 复制为 `config.json.bak`；
3. 原子替换主配置。

配置读取失败时依次：

1. 将损坏主配置保留为 `config.corrupt-<时间戳>.json`；
2. 尝试恢复 `config.json.bak`；
3. 扫描 `Profiles/pN` 重建最小环境列表；
4. 没有任何可恢复数据时才使用默认配置。

`lastUsed` 由环境启动/停止流程写入 Profile 配置。旧配置或磁盘重建时，环境目录修改时间只作为兜底值。

读取配置时还会过滤非法编号和重复 folder，避免异常但仍可解码的 JSON 导致运行时状态字典冲突。磁盘重建只接受实际目录，不把同名普通文件识别为环境。

## 当前双仓库检查（2026-09-26）

基线：macOS `f1891c3` 加已有未提交改动；Windows `f312c2f`。此报告是同一 AI 的代码自查，不是独立评审。已修复问题由代码和回归测试追溯，本文保留当前契约、平台差异与验收边界。

### 用户确认及行为对齐

- 两端首次生成及后续新建环境默认开启采集、关闭差异；旧配置缺字段、显式关闭和磁盘重建不被迁移为开启。
- 有效配置对应目录缺失时保留名称、备注与模式并补建目录；这不会恢复丢失的 Chrome 登录数据。删除时先持久化移除结果，再移动到废纸篓／回收站；保存失败不移动，移动失败回滚，避免下次补建空环境。
- 外链目标未指定时选择最小编号环境；删除目标环境时清空目标，避免编号复用后误指向新环境。
- Windows 批量采集操作与 macOS 一样只作用于当前筛选内可编辑环境，并合并为一次保存，备份保持批量修改前的状态。
- Windows 损坏主配置保留诊断副本，分别提示备份恢复、磁盘重建和默认回退；引擎状态刷新同步通知高级信息字段。

### 保留的平台差异

| 能力 | macOS | Windows | 判断 |
| --- | --- | --- | --- |
| UI / 常驻入口 | SwiftUI / 菜单栏 | WPF / 托盘 | 保留平台原生实现 |
| 浏览器程序 | 应用数据目录的独立 Chrome 副本 | 系统 Stable Chrome，明确选择后可用 Edge | 已有设计边界，保留；profile 仍各自隔离 |
| 安装和更新 | DMG、Sparkle 应用内更新 | MSI/ZIP、打开 Release 下载更新 | 保留；不要求版本号一致 |
| 运行中双击 | 不保证精确置前 | 尝试置前 Chrome 主窗口 | 保留 macOS D-008 的权限边界 |
| 外观 | 浅色、深色、跟随系统 | 当前浅色主题 | 功能缺口；是否补 Windows 深色模式待产品决定 |
| 配置之外的磁盘目录 | 主配置正常时不自动补入 | 启动时补入合法目录 | 暂保留；自动发现可能改变手动恢复/删除语义，需另行决定 |
| 目标架构 | Apple Silicon / macOS 13+ | Windows 10/11 x64 | 平台差异 |

### 验证和剩余风险

- Swift：20 项 XCTest 全部通过，Debug 与 arm64 macOS 13 Release 构建通过。覆盖模式兼容、配置恢复、删除保存失败及回滚；使用临时数据与构建目录。
- macOS：隔离源码应用实际检查主窗口、设置、模式管理、深浅色、德语长文本、筛选及运行中禁用状态；真实 Chrome 启停、41001 采集端点与新页面差异注入（4 核 / 4 GB）通过。
- Windows：临时 .NET 8.0.100 在 macOS 交叉编译 WPF，0 警告；30 项契约断言通过，包含受控子进程重复关闭、关闭中禁止重启、完成后重启及通知。七语言资源键、文档和差异格式检查通过。
- 尚未验收：Windows 原生 UI / Chrome / Edge、真实废纸篓和回收站、浏览器安装更新、系统外链、CDP 断线重连、并发启动和退出超时。交叉编译及受控子进程测试不等于这些实机流程通过。
- macOS 外链异常提示目前只保留一次调用中的首条 URL；多条 URL 同时失败时的批量恢复仍有缺口。
- 单个页面注入失败后的逐 target 重试与错误展示仍不完全一致；两端都不承诺首个页面脚本执行前完成差异注入。
- Chrome 签名/来源校验仍需兼顾官方手动安装；本轮不增加权限或强制签名策略。
- Windows 官方下载页面仍使用 `.cn`，切换 `.com` 优先及失败回退属于后续体验改进。
