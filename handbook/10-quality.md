# 测试、评审与质量

> 适用状态：启用。验证入口以仓库脚本和 workflow 为准。

## 验证入口与完成标准

| 范围 | 入口 | 通过条件 | 限制 |
| --- | --- | --- | --- |
| 单元 / 契约测试 | `cd BrowserIsolator && swift test` | XCTest 全部通过 | 覆盖端口规则、Chrome 参数、新建默认模式及旧配置模式兼容 |
| Debug 构建 | `cd BrowserIsolator && swift build` | 编译成功 | 不等于 UI 或系统集成通过 |
| arm64 Release | `cd BrowserIsolator && swift build -c release -Xswiftc -target -Xswiftc arm64-apple-macosx13.0` | 编译成功 | CI 在 macOS 14 执行 |
| 可运行应用 | 根目录 `./build.sh` | `.app` 可启动且依赖/资源完整 | 会生成本地产物，结束后按需清理 |
| 文档 | `python3 handbook/tools/check_docs.py --strict-init` | 0 错误；提醒逐项判断 | 不验证业务事实和外网 |
| 静态差异 | `git diff --check` | 无空白错误 | 不代替代码测试 |

测试文件 `BrowserCompatibilityTests.swift` 固定以下跨平台契约：基础模式无端口；仅差异模式用 40000 段；采集或组合模式用 41000 段；调试只绑定本机；启动参数不包含 `--test-type`。

## 当前质量问题与风险

模式默认值测试覆盖首次配置、新建环境、旧配置缺字段与显式值、关闭采集后的编码重载。`ConfigStoreTests` 使用临时目录覆盖首次启动后直接重启、正常配置不重写、备份/磁盘/默认恢复、初始保存失败和恢复保存失败提示；不操作用户运行数据。`ConfigRecoveryTests` 另覆盖删除保存失败时不移动目录、移动失败回滚及成功删除后重载。

| 编号 | 程度 | 证据与影响 | 当前处理 |
| --- | --- | --- | --- |
| Q-001 | 已确认，中 | 配置恢复已有基础回归；进程收口、CDP 重连和外链仍缺少自动化覆盖 | 按真实故障风险逐步补测试 |
| Q-002 | 待规划，中 | 下载的 Chrome 仅验证路径和可执行权限，未验证签名 / Team ID | 先设计与手动安装兼容的策略 |
| Q-003 | 待验证，中 | 主窗口关闭时外部 URL 提醒的前台可见性依赖真实 macOS 行为 | 做人工端到端验证 |
| Q-004 | 维护风险，低 | `BrowserManager` 同时承担进程、下载、配置、外链和状态职责 | 无明确收益前不进行大拆分 |

旧评审中已经修复的问题（HTTP 状态、端口失败、WebSocket 生命周期/超时、配置错误提示、目录扫描竞态等）不再保留逐条流水账。若回归则按新证据登记，并优先补可重复测试。

双仓库代码自查、已修复缺陷及尚未统一的行为见 [跨平台对齐报告](../docs/windows-alignment.md)。`ConfigRecoveryTests` 补充身份过滤、磁盘恢复、备份保存与大编号边界。

## 手动回归重点

涉及核心逻辑时按改动选择覆盖：首次 Chrome 下载、安装失败恢复、环境创建与编号复用、四种模式和端口冲突、启动/关闭/全部关闭/异常退出、外链进入运行中和启动中环境、配置主文件/备份/磁盘三级恢复、删除到废纸篓、三种语言、外观与窗口恢复、Sparkle 检查和重启。

UI 改动需实际查看；当前 AI 自查不能称为独立代码评审。构建产物、临时日志和截图不作为永久质量记录。

## 本地自动化验证

共享 `automation/tests/integration.mjs` 使用临时浏览器数据与本地页面域，对两个原生核心验证结构分页/限额、iframe/Shadow DOM、交互、动态条件、取消、导航旧引用、DOM/AX 文件、截图像素位置、分块、请求去重和参数校验。回归额外覆盖只读/非文本/无效数值输入保持原值、按名称等待与操作完成、ARIA/fieldset 禁用一致性、显式零位移、结束监听的数量/总字节容量淘汰、摘要裁剪及已完成记录的取消幂等。Swift/C# CLI 和 MCP 另外验证 IPC、能力协商、默认禁图、显式图片及会话资源限制。运行环境与未验收平台记录在 [01](01-current-status.md)，用法见 [14](14-automation.md)。

自动化 UI 用独立源码副本、bundle ID 和临时数据查看服务正常/错误、CLI 缺失/禁用、复制配置、三语言及深浅色；不得直接运行生产构建去修改用户数据。Windows 缺乏原生环境时，只记录静态资源和构建结果，不宣称视觉验收。
