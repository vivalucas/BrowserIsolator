## 事实与文档分工

代码说明当前实现，用户确认的需求说明预期。版本以 `Info.plist` 为准，依赖以 `Package.swift` 和 `Package.resolved` 为准，配置结构以 `Models.swift` 为准，端口与启动参数以纯函数和契约测试为准。

当前约定直接更新，过期内容删除；重要理由留在 11，完整修改历史交给 Git。未解决问题、未提交的唯一工作和实际验证缺口必须保留。根 README 面向用户，AGENTS.md 维护核心协作规则，本文件维护导航和流程，CLAUDE.md 只导入 AGENTS.md。

## 检查工具

在项目根目录运行：

```bash
python3 handbook/tools/check_docs.py --strict-init
```

工具只读检查核心文件、Claude 导入、本地 Markdown 链接、00/01 占位符和篇幅；不验证业务事实、外网、锚点或 AI 是否遵守规则。再运行 `git diff --check` 检查差异格式。

## 开发与协作

1. 检查 `git status --short --branch`、当前分支和 upstream；读取 01 和任务相关文档。
2. 明确“需求—当前实现—本轮改动—验证方式”。小修复简述即可；跨模块、数据兼容、发行或长期行为变化先写精简计划。
3. 保留用户和其他任务的修改。共享文件重叠时协调顺序；文档登记不是文件锁。
4. 按当前架构实现，优先复用已有状态、组件和恢复机制。改变产品含义、破坏兼容或增加系统权限时先讨论。
5. 运行与影响相称的验证，更新发生变化的当前事实和交接状态。

## Git 与跨设备同步

- 沿用当前分支；未经用户指令不新建/切换分支、不建工作树。
- 提交、推送、版本、标签、Release 和部署分别需要相应授权。普通 push 到 `main` 会运行 CI；`v*` 标签会创建公开 Release，不能把打标签当作普通同步。
- 开工可 fetch；只有开发或已授权同步任务，在工作区干净、upstream 明确且仅落后时才可快进。文档整理和只读评审不自动合并远端代码。
- 工作区有修改时不自动 stash、reset 或清理。历史分叉先说明双方改动和整合方案；不自动 rebase、强推或删除分支。
- “推送 / 收工同步”包含提交本轮归属明确的必要改动并推送当前分支。推送前重新 fetch、检查差异和触发的外部动作；推送后核实远端提交。
- Git 不同步另一台设备尚未推送的工作。真实配置、Chrome、Profiles、UserDefaults、密钥和构建目录不通过 Git 换机。

## 日常收尾

- 对本轮全部要求和累计改动做一次整体检查；验证范围和风险匹配。
- 核心逻辑至少运行相关 XCTest 和构建；文档运行检查工具。UI 变更可运行时实际查看界面，并报告未覆盖状态和平台。
- 更新 01 的活跃状态和最近验证；长期取舍写 11，普通完成记录不写开发流水账。
- 只清理本轮生成且无需交付的 `.build`、`.app`、`.swiftpm`、dSYM、临时截图和日志，不删除依赖、正式文档或用户文件。
- 最终说明完成内容、验证结果、未覆盖范围、当前分支及提交/推送状态。

## 专项评审（默认只读）

全面评审先声明基线和覆盖范围，阅读相关实现、测试和约定后逐条复核。报告区分项目理解、确认问题、待验证问题和体验建议；每项给触发条件、位置、影响、证据、建议和优先级，不凭关键词判断。

默认不改代码或文档。用户授权保存时，简短结论写入 10，较长报告建立 14+ 专题。已修复且无长期价值的旧问题删除；能防复发的行为优先进入测试，同一 AI 的复核标为自查。

## 上下文维护

文档随任务更新，不按对话追加日志。阶段结束或内容重复时：保留有效约定、未解决问题、用户约束和必要复现信息；删除过时过程；将重要原因压缩进 11；长资料只在 12/10 留索引。不确定内容标“待复核”并写依据，不能为了变短丢失真实风险。

## 信息保护

真实 Sparkle 私钥、Cookie、密码、浏览器数据和敏感样本不得进入仓库。示例只写变量名或假值。发现凭据泄露时说明影响并按授权轮换，不在文档中再次复制。
