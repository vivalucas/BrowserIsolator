# 功能与业务约定

> 适用状态：启用。以当前代码和 1.9.0 用户文档为准。

## 当前功能地图

| 功能 / 入口 | 用户任务 | 当前实现 / 代码依据 | 验收重点 |
| --- | --- | --- | --- |
| 主窗口环境列表与详情 | 查看、选择、启动和关闭环境 | `App.swift`、`BrowserManager.swift` | 运行状态、最近使用、大小、错误和操作一致 |
| 环境管理 | 创建、命名、备注、删除 | `BrowserManager`、`Models` | 编号复用；运行/启动/关闭中不可删；目录移到废纸篓 |
| 模式管理 | 选择基础、采集、差异或组合模式 | `SettingsView`、`FingerprintModeManagerView` | 状态中的环境不可改；保存后下次启动生效 |
| CDP 注入 | 给差异模式页面注入稳定值 | `FingerprintInjector.swift` | 当前及新 page target 均处理；失败不阻断核心隔离 |
| 外部链接 | 将其他 App 的 http/https 链接转入指定环境 | `AppDelegate`、`BrowserManager.openExternalURLs` | 启动中链接排队；无环境或 Chrome 未就绪时可恢复 |
| Chrome 管理 | 自动下载、安装、验证和重新下载 | `BrowserManager`、设置页 | 临时 DMG 清理；安装失败恢复旧副本；运行时不可重装 |
| 配置恢复 | 从备份或磁盘恢复环境清单 | `ConfigStore` | 不因配置损坏隐藏仍存在的 profile 目录 |
| 更新与发布 | 检查并安装应用更新 | `SparkleUpdater`、GitHub Releases | appcast 签名有效；更新重启后主窗口可见 |
| 多语言和外观 | 7 种语言、浅色/深色/跟随系统 | `Localization.swift`、`AppAppearance` | SwiftUI 与 AppKit 窗口外观同步 |

## 关键规则

### 环境身份和生命周期

- `folder` 是稳定身份，格式为 `pN`；新增环境复用最小空缺正整数。
- `displayName` 和 `note` 是可变展示信息，不能替代 `folder` 作为关联键。有效配置的目录缺失时保留信息并补建空目录，不宣称恢复原有登录数据。
- 启动流程：验证 Chrome → 按模式分配端口 → 启动独立进程 → 记录状态和最近使用时间 → 差异模式启动注入器。
- 停止流程：取消待处理链接与注入器 → SIGTERM → 最多等待约 5 秒 → 必要时 SIGKILL → 清理运行状态。
- 删除只允许静止环境，并将 profile 目录移到废纸篓；先保存移除后的配置，保存失败不移动目录；移动失败恢复原配置并提示错误。

### 模式和端口

| 模式 | `collectorDebugEnabled` | `fingerprintEnabled` | 首选端口 | 页面注入 |
| --- | --- | --- | --- | --- |
| 基础 | false | false | 无 | 无 |
| 仅差异 | false | true | `40000 + N` | 有 |
| 仅采集 | true | false | `41000 + N` | 无 |
| 采集 + 差异 | true | true | `41000 + N` | 有 |

端口只绑定 `127.0.0.1`；若首选端口不可用，向后最多尝试 10 个，失败时在该环境显示错误。实际端口只存在于运行状态中，不写回配置。此表是当前 macOS/Windows 兼容契约，修改时必须同步测试和 `docs/windows-alignment.md`。

差异值按环境编号稳定计算：CPU 核心数在 4、6、8、10 中轮换，内存值在 4、8、16 中轮换。`instanceNumber <= 0` 时用 1 兜底；配置加载阶段也会过滤非法编号。

### 配置和恢复

- 默认新配置包含 `p1`、`p2`、`p3`；首次生成和后续新增环境均默认开启采集、关闭差异。已有配置保持原值，旧配置缺少采集字段时仍关闭；磁盘重建沿用两种模式关闭的恢复规则。新增字段解码必须有兼容默认值。
- 保存先写临时文件，再复制旧主文件为 `config.json.bak`，最后替换主文件。
- 主文件解码失败时先保留为 `config.corrupt-<时间戳>.json`，再尝试 `.bak`，再扫描真实的 `Profiles/pN` 目录；都不可用才回到默认配置。
- 恢复提示必须区分备份恢复、磁盘重建和默认回退，不能笼统宣称“已恢复”。

## 用户路径与异常恢复

- Chrome 未就绪时进入下载流程；下载失败可重试或手动放置 Chrome。
- 外部链接只接受 http/https。目标环境已运行时另启 Chrome 调用打开链接；正在启动时先排队；无可用环境或 Chrome 未就绪时显示可复制链接的提示。
- 配置保存失败必须弹窗并保留当前内存状态，不能静默吞掉错误。
- 注入是增强能力：连接或单个 target 注入失败记录错误并重试，不得让基础 profile 隔离失效。
- UI 上的模式、端口、错误和运行状态必须来自当前 `BrowserManager` 状态，不能用固定端口或静态描述替代。
