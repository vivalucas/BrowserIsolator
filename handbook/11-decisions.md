# 决策与经验

仅保留仍约束当前实现、能解释边界或防止重复踩坑的取舍。以下内容由旧 ADR、设计决策和当前代码压缩而来。

## D-008：暂不实现运行中环境的精确窗口置前

- **状态与日期**：当前有效；2026-05-24。
- **选择与依据**：双击未运行环境可启动；运行中环境不承诺精确切到对应 Chrome 窗口。仅激活进程不保证目标窗口，Accessibility/AppleScript 会增加权限和脆弱性，偏离轻量工具边界。
- **重评条件**：能建立稳定的 profile—进程—窗口映射，或真实用户需求足以覆盖额外权限与维护成本。

## D-007：更新安装前关闭宿主窗口，重启后主动恢复主窗口

- **状态与日期**：当前有效；2026-05-24。
- **选择与依据**：Sparkle 安装/重启前关闭应用自己的主窗口和设置窗口，但跳过 Sparkle 窗口；启动后短重试寻找主窗口并置前，并在激活/reopen 时兜底。固定单次延迟无法稳定覆盖 SwiftUI 窗口创建时序。
- **边界**：这保证的是应用窗口恢复，不代表每次系统环境下都已完成真实更新验收。

## D-006：使用 Sparkle + GitHub Releases，暂不提供 Homebrew 更新源

- **状态与日期**：当前有效；2026-05-24。
- **选择与依据**：Sparkle 解决普通 DMG 用户的应用内更新，GitHub Releases 继续托管 DMG/appcast。暂不让 Sparkle 和 Homebrew 同时管理同一安装实例，以免版本状态和用户预期混乱。
- **重评条件**：出现明确的 Homebrew 安装需求，并能清楚区分安装来源与更新归属。

## D-005：外部链接由应用级默认浏览器入口转发到指定环境

- **状态与日期**：当前有效；2026-05-24。
- **选择与依据**：macOS 只注册应用级默认浏览器，不能把每个 profile 注册成独立浏览器。BrowserIsolator 接收 http/https URL，再用 UserDefaults 中的目标 folder 选择环境；入口集中在设置页。
- **边界**：无可用环境、Chrome 未就绪或目标正在启动时必须给出提示或排队，不能静默丢链接。

## D-004：配置采用主文件、备份、磁盘重建三级恢复

- **状态与日期**：当前有效；2026-07-11。
- **选择与依据**：配置损坏不应让磁盘上仍存在的环境从界面消失。保存前保留 `.bak`；加载主文件失败后依次尝试备份、扫描 `Profiles/pN` 和默认配置，并保存损坏副本。`lastUsed` 显式持久化，目录修改时间只作兜底。
- **执行**：新字段提供旧配置默认值；批量修改一次保存；重建过滤非法编号、重复身份和非目录。

## D-003：采集与 navigator 差异化解耦，新建环境默认支持采集

- **状态与日期**：当前有效；2026-07-11，端口契约于 2026-09-09 与 Windows 对齐；2026-09-26 调整新建默认值。
- **选择与依据**：新建环境（含首次生成）默认开启采集、关闭差异，省去每次创建后手动开启采集的步骤；已有环境不迁移，旧配置缺字段和磁盘重建仍按关闭处理。用户可单独关闭采集。基础模式仍不开 CDP。采集只需本机 CDP，不应被迫改变页面 `navigator`；差异模式才创建注入器。仅差异模式使用 `40000 + N`，采集或组合模式使用 `41000 + N`，都只绑定 `127.0.0.1`。
- **代价**：端口冲突回退后，采集方必须读取实际端口；CDP 注入只是轻量差异化，不是反检测承诺。
- **执行**：修改规则时同步 `BrowserCompatibilityTests` 和 `docs/windows-alignment.md`。

## D-002：使用 Swift 并发隔离状态

- **状态与日期**：当前有效；2026-05-06。
- **选择与依据**：UI 和进程状态集中在 `@MainActor BrowserManager`，CDP 连接状态集中在 `FingerprintInjector` actor。相较手工锁或散落 DispatchQueue，编译器可提供更清晰的数据竞争边界。
- **边界**：阻塞式进程 API 仍需显式移出关键执行路径；actor 不自动解决外部进程和网络超时。

## D-001：原生 SwiftUI macOS 应用

- **状态与日期**：当前有效；2026-05-06。
- **选择与依据**：项目仅面向 macOS，SwiftUI 提供声明式原生 UI、深色模式和 Swift 状态集成；AppKit 用于 SwiftUI 不便处理的窗口、事件与平台能力。Electron 的跨平台收益不足以抵消体积和非原生体验。
- **边界**：不为追求“纯 SwiftUI”移除必要的 AppKit 桥接。
